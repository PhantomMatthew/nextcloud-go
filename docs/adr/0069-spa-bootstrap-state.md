# ADR-0069: SPA bootstrap initial-state injection

- **Status**: Accepted
- **Date**: 2026-09-23
- **Deciders**: Project lead
- **Supersedes**: (none)
- **Amends**: ADR-0054 (static-serving follow-up "server-rendered bootstrap
  state" now fully addressed at the core-subset level), ADR-0064 (the
  `ShellBootstrap` interface is extended, not duplicated)

## Context

ADR-0054 serves a pre-compiled Nextcloud web UI statically; ADR-0064 injects
the `requesttoken` into the SPA shell. The remaining first-load error noise
comes from the missing bootstrap payload upstream PHP renders into every
page: the `window._oc_*`/`oc_appconfig` globals, the `<head>` user
attributes, and the initial-state hidden inputs. Without them the dashboard
shows no current user (the user menu reads `<head data-user>`) and URL
generation guesses a wrong webroot on SPA routes.

What the frontend actually reads, verified against upstream sources:

- `core/templates/layout.user.php` emits
  `<head data-user="..." data-user-displayname="..." data-requesttoken="...">`
  ([master layout.user.php](https://github.com/nextcloud/server/blob/master/core/templates/layout.user.php),
  [stable28 layout.user.php](https://github.com/nextcloud/server/blob/stable28/core/templates/layout.user.php));
  the guest/login layout carries only `data-requesttoken`.
- The bootstrap JS is **not** inline in the layout: `oc.js` is generated by
  `core/Controller/OCJSController.php` → `OC\Template\JSConfigHelper::getConfig()`
  ([stable28 JSConfigHelper.php](https://github.com/nextcloud/server/blob/stable28/lib/private/Template/JSConfigHelper.php),
  [stable26 JSConfigHelper.php](https://github.com/nextcloud/server/blob/stable26/lib/private/Template/JSConfigHelper.php),
  [master JSConfigHelper.php](https://github.com/nextcloud/server/blob/master/lib/private/Template/JSConfigHelper.php)).
  It emits `var _oc_webroot=`, `var _oc_appswebroots=`, `var _oc_config={...}`,
  `var oc_appconfig={"core":{...16 sharing keys...}}`, `var _theme=`, and —
  session only — `var oc_userconfig={"avatar":...}`, plus l10n arrays and
  timestamps; it also provides the `core/config` and `core/capabilities`
  initial states. The `$config` key set is identical across 26/28/master
  (28+ adds `enable_non-accessible_features`).
- Consumer side (verified against the local NC 26-era checkout
  `nextcloud-server@13ef475`, matching ncgo's declared 26.0.0 compatibility):
  `core/src/OC/config.js` reads `window._oc_config || {}`,
  `core/src/OC/appconfig.js` reads `window.oc_appconfig || {}`,
  `core/src/OC/webroot.js` reads `window._oc_webroot` and falls back to
  *deducing the webroot from `location.pathname`* — wrong on SPA routes like
  `/apps/dashboard` — so `_oc_webroot` must be injected
  ([core/src/OC sources](https://github.com/nextcloud/server/tree/master/core/src/OC)).
  `@nextcloud/router` reads `OC.config.modRewriteWorking` to decide whether
  generated URLs get the `/index.php` prefix. `core/src/session-heartbeat.js`
  does `loadState('core', 'config')` and **falls back to `OC.config`** when
  the initial state is absent, so `_oc_config.session_keepalive` /
  `session_lifetime` drive the heartbeat even without initial-state.
  `@nextcloud/auth`'s `getCurrentUser()` and `core/src/OC/currentuser.js`
  read the `<head data-user>` / `data-user-displayname` attributes.
- Initial-state convention ([layout.initial-state.php](https://github.com/nextcloud/server/blob/master/core/templates/layout.initial-state.php),
  [InitialStateService.php](https://github.com/nextcloud/server/blob/master/lib/private/InitialStateService.php),
  [nextcloud-initial-state](https://github.com/nextcloud-libraries/nextcloud-initial-state)):
  hidden `<input id="initial-state-<app>-<key>" value="base64(JSON)">`
  elements; `loadState(app, key)` throws when the element is missing unless
  a default is passed.

Constraints from the phase task: extend ADR-0064's injection, don't build a
second pipeline; inject only keys with a faithful data source; anonymous
pages leak zero user/internal information; no new config keys; static assets
stay byte-identical; no new dependencies.

## Decision

1. **One injection pipeline, extended.** `web.ShellBootstrap` becomes a
   single method `Bootstrap(w, r) (token string, state BootstrapState)`;
   `serveShell` feeds both into `injectShell` (`internal/web/bootstrap.go`).
   The ADR-0064 outputs are byte-identical: `<head data-requesttoken>`
   replace-or-insert, the `<script>window.oc_requesttoken="...";</script>`
   block first, no Last-Modified, no 304, `Cache-Control: no-cache`. All
   other assets stay byte-identical.

2. **Injected globals (both states), upstream-named.** One additional
   `<script>` block with `window.<name>=<json>;` assignments, in this order:

   - `window._oc_webroot` = `""` — faithful: ncgo mounts everything at the
     site root (no subdirectory hosting exists). Prevents `webroot.js`'s
     pathname deduction from corrupting every generated URL on SPA routes.
   - `window._oc_config` = exactly five keys:
     - `modRewriteWorking: true` — faithful: ncgo mounts OCS
       (`/ocs/v{1,2}.php/...`), DAV (`/remote.php/...`), and `status.php`
       *without* the `/index.php` prefix, so pretty-URL generation is the
       only shape that resolves. (`false` would 404 every OCS call; the one
       casualty of `true` is `/core/preview`, which ncgo today mounts only
       under `/index.php` — recorded as a follow-up.)
     - `session_keepalive: true` — sessions are kept alive by heartbeat
       (`SessionVerifier.VerifyID` touches the row), matching upstream's
       default `yes`.
     - `session_lifetime: 86400` — the same 24 h default the login handlers
       and session store apply (`web.defaultSessionTTL`); wired through
       `BrowserBootstrap.SessionTTL` so a future configurable TTL stays
       consistent.
     - `version` / `versionstring` — from `internal/version` (new
       `version.String()`), the same source `status.php` and capabilities
       use: `26.0.0.6` / `26.0.0 beta 4`.
   - `window.oc_appconfig` = `{"core": {...}}` with upstream's exact 16-key
     core set (stable26 = stable28 = master), values faithful to ncgo:
     `defaultExpireDateEnabled: false`, `defaultExpireDate: null`,
     `defaultExpireDateEnforced: null` (no share-expiry enforcement
     anywhere; nulls match upstream with the feature off),
     `enforcePasswordForPublicLink: false` and
     `enableLinkPasswordByDefault: false` (link passwords optional per
     `sharing.Service.Create`), `sharingDisabledForUser: false`,
     `resharingAllowed: true` (no reshare restriction exists),
     `remoteShareAllowed: true` (outgoing OCM shares, ADR-0050-era, and
     upstream's default `yes`),
     `federatedCloudShareDoc` = the `docs.nextcloud.com` federated-sharing
     manual URL for the declared server major,
     `allowGroupSharing: true` (group shares, Phase 2k), and the
     internal/remote expiry triplets `false/null/null` like the user one.

3. **Session personalization is head attributes only.** With a valid
   session whose user row exists and is enabled (the auth middleware's exact
   criteria), `injectShell` upserts `<head data-user="<uid>"
   data-user-displayname="<displayName>">`; anonymous responses **strip**
   any operator-baked copies of those two attributes, so the login page can
   never assert a phantom user. Values are HTML-escaped
   (`html.EscapeString`). The script payload is byte-identical across
   states — pinned by a test — so nothing user-specific ever enters a JS
   string context.

4. **Injection-safety by construction.** All JSON is `encoding/json`
   output, which escapes `<`, `>`, `&` as `\u003c` etc. — a payload value
   cannot close the script block. A test with a `</script>`-laden display
   name proves both the attribute and the JSON path.

5. **initial-state: evaluated, not implemented.** The
   `initial-state-<app>-<key>` hidden-input mechanism is the upstream way to
   feed per-app boot data, and JSConfigHelper itself provides `core/config`
   and `core/capabilities` through it. We deliberately do **not** emit
   hidden inputs in this increment: core's session heartbeat already falls
   back to `OC.config`, `loadState` callers that matter pass defaults
   (`settingsNavEntries`, `versionHash`), and faithfully populating
   `core/capabilities` duplicates the OCS capabilities handler's payload for
   no proven consumer. Follow-up condition: when a served frontend bundle is
   observed failing on a *missing-default* `loadState(app, key)`, add a
   hidden-input emitter to `BootstrapState` keyed by (app, key) with
   `core/capabilities` first.

6. **Deliberately not injected** (evaluated against upstream, rejected):
   - `_oc_appswebroots` — consumers default gracefully (`false`/undefined
     property reads); ncgo has no per-app web-path map, so any non-empty
     value would be invented.
   - `_theme` — theming/branding is unimplemented; `window._theme || {}` is
     graceful. A branding follow-up owns this.
   - `oc_userconfig` (avatar) — ncgo has no avatar endpoint; injecting
     `{"avatar":{"version":0,...}}` would promise a route that 404s.
   - `_oc_isadmin`, `_oc_debug`, `backendAllowsPasswordConfirmation`,
     `oc_dataURL`, `nc_lastLogin`, `nc_pageLoad`, the l10n day/month arrays
     — admin concepts and password-confirmation flows ncgo does not
     implement; defaults are graceful (`!!undefined === false`), and
     `nc_*` timestamps would leak session metadata to anonymous pages.
   - `enable_avatars` — the phase task listed it as a candidate; it does
     **not** exist in JSConfigHelper on stable26/28/master. Avatar
     availability upstream is `oc_userconfig.avatar` + capabilities; both
     are out of scope per above.
   - The rest of upstream's `_oc_config` keys (`auto_logout`,
     `blacklist_files_regex`, `loglevel`, `lost_password_link`,
     `no_unsupported_browser_warning`, `sharing.maxAutocompleteResults`,
     `sharing.minSearchStringLength`, `enable_non-accessible_features`) —
     none are read during SPA boot by anything we can verify, and several
     describe PHP-side features; add individually when a consumer is proven.

7. **Anonymous leakage surface.** Anonymous pages receive: the webroot
   (`""`, public), the server version (already public via `status.php`),
   `modRewriteWorking`/session-keepalive booleans, the session lifetime, and
   the sharing default policy — all of which upstream publishes to anonymous
   visitors of the login page through the same `oc.js` payload. No uid, no
   display name, no admin flags, no app lists, no timestamps.

## Alternatives Considered

### Serve an `oc.js` route instead of inline injection
- Pros: byte-shaped like upstream (a separate `text/javascript` response),
  cacheable for anonymous visitors.
- Cons: a second bootstrap pipeline (ADR-0064 already owns shell injection),
  the payload is session-personalized so caching is mostly illusory, and the
  static-only shell constraint (ADR-0054) prefers self-contained HTML.
  Rejected.

### Inject the full upstream key set with best-guess values
- Pros: maximal frontend silence.
- Cons: invents data ncgo does not have (admin state, avatars, l10n arrays),
  and wrong values are worse than missing ones — missing keys hit graceful
  defaults, wrong keys drive wrong behavior. Rejected by the phase
  principle "宁可少注不错注" (rather under-inject than mis-inject).

### Initial-state hidden inputs for `core/config` + `core/capabilities` now
- Pros: one step closer to upstream shape; capabilities payload exists in
  `internal/capabilities`.
- Cons: no proven consumer (heartbeat falls back to `OC.config`); doubles
  the injected bytes on every shell; the (app, key) extension point is
  cheap to add later. Deferred with an explicit trigger condition.

## Consequences

- The dashboard/user menu shows the current user (`data-user` attributes),
  `@nextcloud/router` generates working extensionless URLs, and the session
  heartbeat reads its real interval — the ADR-0054 "server-rendered
  bootstrap state" follow-up is closed at the core-subset level.
- `ShellBootstrap` implementers move from `RequestToken(w, r) string` to
  `Bootstrap(w, r) (string, BootstrapState)`; the only two implementations
  (BrowserBootstrap, the test stub) are updated here.
- ~~Known casualty (accepted): with `modRewriteWorking: true` the files app
  builds preview URLs as `/core/preview?...`, which ncgo does not mount
  (only `/index.php/core/preview`). Follow-up: dual-mount the preview route
  extensionless.~~ **Resolved by ADR-0077** (Phase 5e, 2026-09-23):
  `/core/preview` and `/core/preview.png` are mounted alongside the
  `/index.php` pair, same middleware, same path-agnostic handler.
- Follow-ups: initial-state hidden inputs on the trigger condition in
  §5; `_theme` with branding; `oc_userconfig` with an avatar endpoint;
  ~~extensionless `/core/preview` mount~~ (resolved by ADR-0077).
- `internal/version` gains `String()`; `status.Provider` now uses it.

## Verification

- `internal/web/bootstrap_test.go`: exact key-set snapshots of every
  injected global (`_oc_webroot`, `_oc_config` 5 keys, `oc_appconfig.core`
  16 keys), byte-exact script snapshot, every value parses as JSON
  (`json.Decoder`), session/anonymous script payloads identical,
  `</script>` breakout impossible on both the JSON and attribute paths,
  headless-fragment prepend, baked user attributes replaced.
- `internal/web/static_test.go`: state injection at `/` with head-attribute
  order, anonymous stripping of baked `data-user`/`data-user-displayname`
  (with token refresh intact), HTML-escaped hostile display name and uid,
  ADR-0064 regressions (token at `/`, `/index.html`, SPA fallback; stale
  attribute replacement; assets byte-identical with 304s; injected shell
  never 304s; HEAD has no body).
- `internal/web/login_test.go`: full chain over a real session SQLStore —
  anonymous shell has no `data-user` and public-only state; authenticated
  shell gains `data-user="alice"`/`data-user-displayname="Alice"` with the
  script payload unchanged; `_oc_config` carries the version and
  `modRewriteWorking: true`.
- Gates: `golangci-lint fmt` clean, `gofmt -l` empty, `go test ./...` green,
  `golangci-lint run ./...` 0 issues, `go mod tidy` no-op, `go test -race
  -coverprofile` green.
